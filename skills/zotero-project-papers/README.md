# zotero-project-papers v0.1.1

A small Agent Skill + stdlib-only Python helper that makes **Zotero the canonical paper library** and a repository's `papers/reference/` the **agent-facing working set**.

## What v0.1 does

- searches the current project's Zotero collection first;
- searches the whole local Zotero library second;
- leaves web search to Claude Code / Codex / the host agent;
- binds one repo to one Zotero collection under `Projects/`;
- adds existing Zotero papers to the current project without downloading them again;
- imports selected downloaded PDFs through **Zotero 10 Local API** as stored attachments;
- materializes Zotero-managed PDFs into `papers/reference/`, using hard links when possible;
- generates `papers/reference/papers.json` and `papers/references.bib`;
- never writes `zotero.sqlite` or `Zotero/storage` directly.

## Requirements

- Zotero 10+ running locally.
- Zotero Settings → Advanced → **Allow other applications on this computer to communicate with Zotero**.
- Python 3.10+.

## Installation

The recommended installation path is **CC Switch**. This skill is distributed from a GitHub repository under `skills/zotero-project-papers/`; add that repository in **CC Switch → Skills → Repository Management**, set the repository subdirectory to `skills`, refresh, then install and enable `zotero-project-papers` for Claude Code and/or Codex.

CC Switch should remain the source-of-truth manager for the installed skill. Do not run a separate self-installer or manually overwrite the copies managed by CC Switch.

For development only, the entire `zotero-project-papers` directory can still be copied manually into an agent's skill directory.

## First run

From any research/coding repository:

```bash
python ~/.claude/skills/zotero-project-papers/scripts/zotero_papers.py status
python ~/.claude/skills/zotero-project-papers/scripts/zotero_papers.py init
```

On the first write operation, run:

```bash
python ~/.claude/skills/zotero-project-papers/scripts/zotero_papers.py authorize
```

Choose **Always Allow** in Zotero. The helper stores the resulting local-only Zotero write key in the user's config directory with restrictive file permissions where supported.

## Project files

After initialization, a project typically contains:

```text
repo/
├─ .zotero-project.json
└─ papers/
   ├─ reference/
   │  ├─ papers.json
   │  └─ <project PDFs>.pdf
   └─ references.bib
```

The Zotero library contains:

```text
Projects/
└─ <repo-name>/
```

## Important v0.1 limits

- Requires Zotero 10; it intentionally does not support Zotero 7–9 write bridges.
- Does not perform web search itself. The host agent does that after local misses.
- Does not fetch metadata from Crossref/arXiv itself. The host agent supplies metadata JSON for imported web PDFs.
- Does not use MinerU yet.
- Does not delete Zotero items.
- `sync` is additive unless `--prune` is explicitly requested.
- Hard links require source and destination on the same filesystem/volume. Default fallback is a normal copy; configure `fallback` to `symlink` if preferred.

## Configuration

`.zotero-project.json` is generated by `init` and looks like:

```json
{
  "schemaVersion": 1,
  "collectionPath": "Projects/my-repo",
  "collectionKey": "ABCD2345",
  "referenceDir": "papers/reference",
  "manifestFile": "papers/reference/papers.json",
  "bibFile": "papers/references.bib",
  "fallback": "copy"
}
```
